Search2Get Journal

A first project,
rebuilt properly.

The original Search2Get was hand-written during first year. V4 keeps that history visible, but treats the current experience like a real storefront: product data first, clearer UX, better state handling and a deliberate visual system.

2023 → 2026 · vanilla web
Then

Static pages and manually placed products.

The first version proved the fundamentals: HTML structure, CSS styling and JavaScript written line by line. It also had the limitations you would expect from an early frontend project—fixed content, inconsistent layout, weak responsiveness and no real product state.

Now

A storefront driven by a live catalog.

The current build loads apparel through a product API, normalizes it into one store model and uses the same product objects for homepage merchandising, search, filters, quick view, wishlist, bag totals and checkout simulation.

Engineering decisions

What actually
changed.

The V4 rebuild is less about adding decoration and more about making the frontend behave like a coherent product.

01

One catalog model

Raw API products are transformed into predictable fields for segment, category, INR display pricing, original price, stock, sizes, images, shipping and returns.

02

Product-first imagery

The old fashion portraits and editorial substitutions were removed from the active experience. The store now displays the products it is actually selling.

03

Resilient states

Loading skeletons, empty search states, image fallbacks and an offline catalog fallback keep the interface usable when dependencies fail.

04

Shopping state

Wishlist, bag quantities, shipping threshold, selected sizes and local account/form demos persist without pretending there is a production backend.

05

Responsive system

Desktop, tablet and mobile layouts use the same visual language while controls reorganize instead of simply shrinking.

06

History preserved

The early implementation remains in Git history, so the repository shows growth rather than erasing the project that started it.

Project principle

Don’t hide the old work.
Outgrow it.

The point of this rebuild is not to pretend the first version never existed. It is to make the difference between then and now obvious.
